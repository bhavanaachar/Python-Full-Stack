DAY 19 OF PYTHON - ENCAPSULATION AND ABSTRACTION

ENCAPSULATION

DEFINITION

Encapsulation means bundling data (variables) and the methods that work on that data together inside a single class, and restricting direct access to some of the object's internals. 
It protects data from accidental or unauthorized changes and lets you control how values are read or modified.

Real-life example: An ATM machine. You can withdraw money using buttons, but you cannot directly reach into the machine and change the balance.


ACCESS MODIFIERS IN PYTHON
--------------------------
Python has no strict private/public keywords. It uses naming conventions:

Type       | Syntax     | Meaning
-----------|------------|--------------------------------------------------
Public     | name       | Accessible from anywhere
Protected  | _name      | Should be used only inside the class and its
           |            | subclasses (a convention, not enforced)
Private    | __name     | Name-mangled; cannot be accessed directly from
           |            | outside the class


EXAMPLE 1: Public, Protected, Private

class Student:
    def __init__(self, name, age, marks):
        self.name = name          # public
        self._age = age           # protected
        self.__marks = marks      # private

    def show(self):
        print("Name:", self.name)
        print("Age:", self._age)
        print("Marks:", self.__marks)

s = Student("Ravi", 20, 85)
print(s.name)       # works
print(s._age)       # works (but not recommended)
# print(s.__marks)  # AttributeError: private variable
s.show()

Output:
Ravi
20
Name: Ravi
Age: 20
Marks: 85


NAME MANGLING

Python renames a private variable internally to _ClassName__variable. So it can still be reached:

print(s._Student__marks)   # 85

This shows that private in Python is about preventing accidents, not about strict security.


EXAMPLE 2: Getters and Setters

Used to read and update private data safely, with validation.

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def set_balance(self, amount):
        if amount >= 0:
            self.__balance = amount
        else:
            print("Invalid amount")

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
        else:
            print("Insufficient balance")

acc = BankAccount("Asha", 1000)
acc.deposit(500)
acc.withdraw(200)
print(acc.get_balance())    # 1300
acc.set_balance(-50)        # Invalid amount


EXAMPLE 3: Pythonic way using @property

class Person:
    def __init__(self, age):
        self.__age = age

    @property
    def age(self):              # getter
        return self.__age

    @age.setter
    def age(self, value):       # setter
        if value > 0:
            self.__age = value
        else:
            print("Age must be positive")

p = Person(25)
print(p.age)     # 25  (looks like a normal attribute)
p.age = 30       # uses the setter
p.age = -5       # Age must be positive


BENEFITS OF ENCAPSULATION

- Data hiding and protection
- Validation of data before changing it
- Easier maintenance (internals can change without breaking outside code)
- Better control over how data is accessed
- Cleaner, more organized code



ABSTRACTION


DEFINITION

Abstraction means hiding the complex implementation details and showing only the essential features to the user. The user knows WHAT an object does, not HOW it does it.

Real-life example: Driving a car. You use the steering wheel, brake and accelerator without needing to know how the engine works internally.

Difference from encapsulation:
- Encapsulation = hiding DATA (how it is protected and accessed)
- Abstraction   = hiding IMPLEMENTATION (what is shown vs. how it works)


HOW PYTHON ACHIEVES ABSTRACTION

Using the abc module (Abstract Base Classes):

    from abc import ABC, abstractmethod

Key terms:
- Abstract class  : A class that cannot be instantiated directly. It inherits from ABC.
- Abstract method : A method declared with @abstractmethod that has no (or only a basic) body. Child classes MUST override it.

EXAMPLE 1: Basic Abstract Class

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Rectangle(Shape):
    def __init__(self, length, width):
        self.length = length
        self.width = width

    def area(self):
        return self.length * self.width

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius * self.radius

r = Rectangle(5, 4)
c = Circle(3)
print(r.area())   # 20
print(c.area())   # 28.26

# s = Shape()     # TypeError: Can't instantiate abstract class

EXAMPLE 2: Abstract + Concrete Methods

An abstract class can also contain normal (concrete) methods.

from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

    def receipt(self):                 # concrete method
        print("Payment completed. Thank you!")

class UPI(Payment):
    def pay(self, amount):
        print("Paid Rs.", amount, "using UPI")

class CreditCard(Payment):
    def pay(self, amount):
        print("Paid Rs.", amount, "using Credit Card")

p1 = UPI()
p1.pay(500)
p1.receipt()

p2 = CreditCard()
p2.pay(1200)
p2.receipt()

Output:
Paid Rs. 500 using UPI
Payment completed. Thank you!
Paid Rs. 1200 using Credit Card
Payment completed. Thank you!

EXAMPLE 3: Child class forgets to implement the abstract method

class Animal(ABC):
    @abstractmethod
    def sound(self):
        pass

class Dog(Animal):
    pass            # sound() not implemented

# d = Dog()         # TypeError: Can't instantiate abstract class Dog
                    # with abstract method sound

RULES OF ABSTRACTION IN PYTHON

1. The class must inherit from ABC.
2. Abstract methods are marked with @abstractmethod.
3. You cannot create an object of an abstract class.
4. A child class must implement ALL abstract methods, otherwise it also becomes abstract and cannot be instantiated.
5. An abstract class can have constructors, variables and normal methods.


BENEFITS OF Abstraction

- Reduces complexity by hiding unnecessary details
- Forces a common structure on all child classes
- Improves code reusability and maintainability
- Makes code easier to extend (add new classes without changing old code)

ENCAPSULATION vs ABSTRACTION

Point          | Encapsulation                  | Abstraction
---------------|--------------------------------|---------------------------
Purpose        | Protect and bind data          | Hide implementation
Focus          | How data is accessed           | What the object does
Achieved by    | Private/protected members,     | Abstract classes and
               | getters/setters, @property     | abstract methods (abc)
Level          | Implementation level           | Design level
Example        | Private balance in an account  | Shape.area() with each
               |                                | shape defining its own
